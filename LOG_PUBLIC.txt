### Milestone: LightGBM Baseline and AMEX Metric Evaluation

**Date:** 11 October 2026

**Objective:** Train a first credit-risk classification model and evaluate its performance using general classification metrics and the AMEX competition metric.

**Model**
- Algorithm: LightGBM binary classifier.
- Training customers: 321,238.
- Validation customers: 68,837.
- Engineered features: 365.
- Best iteration: 739, selected through validation early stopping.
- Random seed: 42.
- Model artifact: `models/lightgbm_baseline.txt`.

**Validation metrics**
- ROC-AUC: 0.961312.
- Average Precision: 0.898133.
- Normalized Gini: 0.922623.
- Defaults captured in the top 4%: 15.3669%.
- AMEX metric: 0.538146.
- Validation target rate: approximately 25.8931%.

**Feature importance**
- The leading feature by gain was `latest__P_2`, followed by `mean__P_2`, `latest__B_9`, and `latest__B_1`.
- Feature importance was exported to `reports/lightgbm_feature_importance.csv`.

**Artifacts**
- `models/lightgbm_baseline.txt`
- `reports/lightgbm_baseline_metrics.json`
- `reports/amex_validation_metrics.json`
- `reports/lightgbm_feature_importance.csv`

**Interpretation and limitations**
- Initial validation ranking performance is strong on the competition dataset.
- The AMEX metric provides an additional measure of how effectively the model prioritizes defaults among the highest-risk customers.
- The competition's class sampling means the observed target rate must not be interpreted as a real-world portfolio default rate.
- The current experiment uses a random customer-level split and full-history summary features. It does not yet establish out-of-time or early-warning performance.
- Feature importance reflects model behavior, not causal effects.

**Next steps**
1. Run feature-ablation experiments for features with more than 99% and 95% missingness.
2. Compare the AMEX metric and supporting validation metrics against the baseline.
3. Investigate risk deciles and default capture at different review capacities.
4. Keep the test partition untouched until model selection is complete.
5. Subsequently design a time-based evaluation if the project is to make early-warning claims.
